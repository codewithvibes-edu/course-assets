# Anti-Bloat Rubric

Why this exists: knowledge bases do not die from too little. They die from too
much. Append-forever turns a useful base into a junk drawer the agent scans
slowly and trusts wrongly. Run this on a cadence.

## Delete or consolidate if

- The line is stale.
- The decision was reversed.
- The same fact appears in two places.
- The note repeats a source file the agent can already read.
- The note is longer than needed for routing.
- The index does not match the body.
- The agent would need to read five files to answer one basic question.

## Pass bar

The always-loaded memory fits on one screen or one tight page.

## How to run it

1. Pick a cadence (weekly for an active agent, monthly for a stable one).
2. Walk the always-on files top to bottom against the list above.
3. Consolidate overlapping notes into fewer, denser ones.
4. Delete reversed decisions; supersede with a dated line if history matters.
5. Re-check the index against the body. Fix mismatches.

Counterintuitive but real: cutting a base from hundreds of files to a couple
dozen makes the agent sharper, not poorer. It scans less, the index stays
loadable, and signal-to-noise per file goes up. Density beats volume.
