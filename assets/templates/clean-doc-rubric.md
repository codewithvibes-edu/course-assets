# Clean-Doc Rubric

Why this exists: agents read your docs as instructions. A messy doc is a messy
instruction. This is the bar for any markdown an agent (or a teammate) has to act
on.

## A clean markdown doc

- Starts with why the doc exists.
- Names the owner and last-reviewed date.
- Uses headings as navigation, not decoration.
- Keeps one idea per section.
- Puts examples near the rule they explain.
- Links to source docs instead of duplicating them.
- Marks stale sections or deletes them.
- Ends with next action or usage instructions.
- Can be skimmed in under two minutes.

## How to use it

1. Read the doc top to bottom once, fast.
2. If you cannot say why it exists by the end of the first screen, fix the open.
3. If two sections say the same thing, merge them.
4. If a section duplicates a file the reader can already open, replace it with a
   link.
5. Confirm the last line tells the reader what to do next.

The single highest-leverage line in any doc is the first one: why it exists. Most
docs skip it and the reader spends a minute reverse-engineering the point.
