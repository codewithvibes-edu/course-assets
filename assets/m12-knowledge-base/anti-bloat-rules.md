# Anti-bloat rules for memory

Paste this block into your agent's standing instructions. It is the
single discipline that most prevents a knowledge base from rotting.

## Standing rules

1. **Append, do not spawn.** When there is something new to remember, add
   it to the note that already covers that topic. Create a new note only
   when one genuinely does not exist. "New note every time" is the
   default that kills knowledge bases.

2. **Lead every note with a one-line summary.** Keep it honest and
   current. The summary lines are the index the agent scans first; a
   stale one routes the agent confidently to the wrong place.

3. **Consolidate on a cadence.** Periodically collapse overlapping notes
   into fewer, denser ones. Fewer files means a smaller index, which
   means the always-loaded layer stays under the context ceiling.

4. **Prune the stale.** Delete a reversed decision, or supersede it with
   a dated line. A reversed decision left in the base is a lie the agent
   will act on with full confidence. Recency-based forgetting plus dedupe
   beats append-forever.

5. **Keep the always-on layer to one screen.** Detail lives in linked
   files the agent retrieves only when relevant. If the index outgrows
   the window it truncates silently and the agent goes quietly dumber.

## Anti-bloat checklist (review on a cadence)

Delete or consolidate a line if:

- It is stale.
- The decision was reversed.
- The same fact appears in two places.
- It repeats a source file the agent can already read.
- It is longer than needed to route the agent to the detail.
- The index does not match the body.
- The agent would need to read five files to answer one basic question.

**Pass bar:** the always-loaded memory fits on one screen or one tight
page. Density beats volume.
